# Explain the system before the bug

When explaining an investigation or an unfamiliar flow, lay out the system model before the problem: the actors, the objects, their states, and the operation in question. Then point at where it breaks.

- **Answer follow-ups narrowly.** Answer the question asked, not the next three.
- **Park new findings.** Cases you discover mid-answer and hypotheses you haven't verified go in a separate list at the end, not woven into the explanation.
